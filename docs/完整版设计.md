# DSH 功能体检助手完整设计

日期：2026-11-13。状态：用户已确认完整方案及首发处理边界，进入实现；尚无已验收的可安装产品版本。当前接口基线为 DSH 0.2.2-rc.2。

本插件帮助普通用户在开工前判断当前会话能否执行一项任务：缺什么、证据是什么、有哪些替代办法，以及哪些处理可以经确认后执行。它检查执行条件，不保证最终任务质量，也不把诊断通过当作安全保证。

## 一 产品目标与已确认选择

- 面向社区用户，而非只服务个人环境或某一个行业。
- 第一版同时提供自然语言需求和常用任务入口，共用同一套诊断结果。
- 完整流程包括任务理解、能力检查、最小测试、解释与替代方案、受控处理、复检。
- 独立插件，不修改安装包核心，不替换主模型，不要求另一套模型账号。
- 首批覆盖联网搜索、文件与读图、Office、浏览器和 MCP。每类标明实际检查深度，不以未适配等同于不支持。
- 官方支持计划与开发并行；报名成功不是获批，不把未确认的 Token 支持作为开发预算。

拟用 TypeScript 编写宿主插件与检查器，前端使用 DSH 的客户端扩展接口及现有组件。具体 npm 包名、开源许可证、发布账号和公开时间在发布前确定，本方案不授权对外发布。

## 二 方案比较与选择

| 方案 | 优点 | 局限 | 结论 |
|---|---|---|---|
| 只有 Skill 与提示词 | 快，易分发 | 容易凭工具名字猜能力；缺少可靠状态与权限证据 | 不作为主体 |
| 原生插件，确定性检查器，加当前会话的需求解析 | 能接入会话级工具与宿主能力；自然语言与任务入口一致 | 需要精确版本适配与端到端验证 | 采用 |
| 另一套常驻 Agent 和自动配置管家 | 可执行复杂修复 | 增加调用费用、凭据和权限面；重复宿主能力 | 首版不采用 |

已有社区 Doctor、备份、升级及生图插件可以作为可选适配对象，不默认捆绑安装，不复制其全部功能。我们的主要区别是从当前任务出发，而不是再做一个软件包清单。

首版不做全能安装器、宿主更新器、凭据管理器或独立救援程序。DSH 无法启动、当前会话完全不能执行工具时，本插件也可能无法工作，应明确转向已有的进程外诊断与恢复手段，不承诺从宿主完全失效状态自行修复。

## 三 用户流程

### 自然语言入口

用户在已有会话里说“检查能否读取这些 PDF、联网检索并输出 PPT”。当前会话模型把需求转换为结构化任务意图，再调用只读检查工具。没有隐藏的第二模型，也不绕过当前会话的模型路由、权限和计费。

独立任务入口输入自然语言时，先明确显示将把文本送入用户选定的当前会话，按普通对话消耗额度；不悄悄向后台发模型请求。仅选择内置任务模板可以跳过需求解析的模型调用。

模型只能提出待检查的能力与参数，不能提供“已验证”的结论、执行代码、修复脚本或批准凭据。检查器返回的事实与建议分开。

### 通用流程

1. 确定当前会话、任务、显式指定的输入文件和目标。歧义会影响检查结果时，只澄清必要信息。
2. 进行只读检查，立即说明已知条件、阻塞、待确认与替代路线。
3. 若用户需要实际验证，先展示测试会访问什么、是否写文件、可能的调用费用和超时。
4. 用户选择测试后，使用受限探测器执行，保留取消与失败结果。
5. 可处理的问题生成明确操作计划；支持自动执行的动作经确认后执行，其他动作指向宿主设置或操作说明。
6. 重取当前状态并复检。旧报告保留为历史，不被新状态悄悄覆盖。

任务可部分就绪。例如本地文件可读但搜索后端不可用，应允许用户选择先做本地整理，而不是将整件事一律标为失败。

## 四 诊断含义

每项能力分四个维度记录，避免一个布尔值混合所有状态：

| 维度 | 取值示例 | 含义 |
|---|---|---|
| 当前可调用性 | available / absent / unknown | 是否在本次检查对应的调用范围内 |
| 准备条件 | satisfied / unmet / unknown | 模型、服务、权限和输入条件是否具备 |
| 验证状态 | not_run / passed / failed / cancelled | 是否执行了指明范围的实际测试 |
| 时效 | current / stale / unknown | 是否仍适用于当前环境 |

面向用户的结果为：待准备、已知阻塞、具备条件但未测试、指定测试通过、指定测试失败、待确认、已过期。取消或用户拒绝不能显示成工具损坏。

“指定测试通过”必须附测试对象、范围和时间。一次网页访问成功不等于全部网站可访问；一次文档渲染成功不等于排版完美；模型声明支持图片不等于已完成视觉核验。

聚合规则采用能力依赖图：一个任务需要的能力按 AND 组合，明确的替代路线按 OR 组合。只有至少一条完整路线满足要求，才显示该任务具备执行条件；仍然区分未测试与已测试。未知节点不能被忽略，第三方未适配能力不能直接判无。

## 五 核心架构

1. **任务意图层**：自然语言结构化结果与任务模板统一为 TaskIntent；验证枚举、字段和数量，不接受任意命令。
2. **会话快照层**：读取本轮准入工具、捕获的模型路由、工作目录、权限、已知服务状态；只保留诊断所需字段。
3. **能力适配层**：为搜索、文件、图片、Office、浏览器、MCP 分别提供版本化的证据解释和探测定义。
4. **诊断规则层**：确定性规则产生状态与原因码，不让模型把缺少证据补写为通过。
5. **探测与处理层**：由宿主执行管线承接有副作用的动作，单独管理确认、取消、预算、前置条件及回执。
6. **报告层**：会话结果和可视报告使用同一份结构化记录，不分别计算结论。

拟提供三个模型工具：

| 工具 | 责任 | 默认边界 |
|---|---|---|
| readiness_check | 校验任务意图，读取本轮能力，生成报告 | 不调用外部模型，不发探测请求 |
| readiness_probe | 生成探测计划或执行已确认的探测 | 只接受内置探测 ID 和严格参数 |
| readiness_remedy | 提供处理计划、执行受支持动作、复检 | 不接受任意 shell；没有有效确认不能执行 |

实际工具名须在实现时检查冲突。状态查询和报告读取可使用宿主 Remote，不为每个内部动作扩张模型工具目录。

能力适配须校验准确宿主版本、已知服务契约和必要的 schema 指纹。第三方工具即使使用与内置工具相同的名字，也不能自动取得内置探测资格；不能确认来源与行为时，只报告可见的声明。工具描述、文件内容和错误文本都是不可信数据，不参与授权裁决。

## 六 会话级状态的权威来源

### 工具与执行轮次

工具内部优先使用 exec.agent 与 exec.toolSet，调用 tools.schemas(agent, toolSet)。没有 toolSet 时只能获得已注册或作用域可见定义，不能标成本轮可调用。PTC 模式下只暴露 run_code 是执行形式，不代表终端能力工具消失。

本轮模型从 agent/pre-step 捕获并绑定 turn、step，不用 agent.model.current() 替代已经准备好的本轮模型：用户可能在执行期间选择了下一轮模型。缺少捕获信息时报告路由未知或有变化，不猜测。

toolSet 随步骤结束失效，报告只能存脱离运行对象的最小快照，不保留工具函数、原始 schema 正文或已失效句柄。工具卸载、替换、权限变更或路由变化后，相关报告失效；即使名字没变也不能复用旧测试结果。

### 不在模型步骤中的界面检查

只读入口不能为了获得结果而自动恢复冷会话、启动 Agent 或执行所有插件的条件回调。已有实时 Agent 时可读作用域定义及适配器的只读状态；最近步骤快照必须带时间和版本。需要本轮精确准入时，由用户在正常会话发起一次检查。

不得调用“看起来只是查询”的 resolveAgent 去隐式恢复会话，也不得把 tools.resolve 当作对任意第三方插件都无副作用的万能体检。

### 模型与文件

精确路由的元数据可通过 llm.resolveModelInfo 查询，但第三方适配器的异步查询不天然等于离线。默认使用已取得的、仍适用的元数据或经核验为本地读取的适配器；其他情况标为待确认，联网查询进入探测计划。

工作目录只读使用 workingDirectory.get；ensure 可能恢复目录并提交变更，不用于纯体检。沙箱边界使用 sandboxPolicy.resolve 的权威结果，不用当前目录推导写权限。文件检查通过宿主文件能力进行，只检查用户选中的对象，不遍历整机。

## 七 首批能力与明确限制

| 能力 | 只读检查 | 可选最小探测 | 不得推出的结论 |
|---|---|---|---|
| 搜索 | 工具准入、已知后端清单、特定路由准备状态 | 用户同意后一次非敏感查询，最多少量结果 | searchReady=true 不是后端健康；有浏览器不等于搜索已验证 |
| 网页抓取 | 工具与适配器是否存在 | 用户同意的固定公共页面，限制响应体和跳转 | HTTP 200 仍可能是验证码页；Promise 成功不等于正文可用 |
| 文件 | 显式输入存在、类型、大小、路径映射和读取权限 | 受限读取少量字节；写入测试仅在许可范围创建唯一合成文件 | 目录可读不等于可写；临时目录可写不等于目标可写 |
| 图片 | 本轮模型声明的输入模态、附件服务、工具准入 | 用户选择后，对合成图片做最小视觉测试 | 读图与生图分开；声明支持不等于已实测 |
| Office | 已有技能、工具动态准入、officeKit 服务、输出映射 | 一份小型合成文档生成/转换/渲染；各能力分开验收 | Office 工具未出现可能只是技能未加载；服务存在不等于引擎能运行 |
| 浏览器 | 已适配连接器与相关工具是否对当前会话可见 | 独立测试页完成打开、读取与关闭，不触碰用户现有标签 | 存在 browser_* 名称不等于当前浏览器已连接 |
| MCP | 命名空间工具、可取得的真实连接状态和代次 | 经确认的握手/listing，严格限制时间与结果 | 工具注册不等于连接健康；握手不证明任意业务操作成功 |

MCP 的 connectionStatusOf 需要真实的所属 Fiber，现有公开声明并未提供一个通用的全实例状态枚举器。首版只对有可靠绑定的集成显示连接状态，否则显示“工具已发现，连接状态未核验”。不读取私有字段补齐。

Office 在已加载技能后，工具从下一步骤开始准入，不能在同一步骤内立即重试一个尚未准入的工具。若授权加载技能，应明确提示会向当前会话加入指令，不将其包装成可无痕撤销的配置修复。

## 八 探测安全与成本

- 分类为元数据读取、本地受限读取、本地写入/进程测试、外部只读请求、可能计费的模型请求。只读体检默认不启动后三类。
- 探测使用合成输入，不发送用户文档正文、密钥或原始会话。确需用户材料时重新明确范围。
- 对外地址采用内置允许清单或用户已配置且获准的目标，验证协议、重定向和网络边界；不让任务文本提供任意内网探测地址。
- 不为获取“健康”而执行任意 MCP 工具或任意可执行文件；stdio 握手会启动进程，不能称为无副作用检查。
- 费用不明时写“费用未知”，限制调用次数、输入和输出上限，不承诺金额硬上限。未明确同意不调用。
- 默认每个探测仅一次；超时或取消时保留未知执行状态，不盲目重试外部请求。
- 工具操作经宿主原有执行与审批管线，不直接调用注册定义的 execute 函数，也不通过文件系统或网络直连绕过拒绝。
- 宿主审批策略为 never 时，所有需要审批的动作保持拒绝/待人工处理；插件按钮不能替代被宿主拒绝的授权。

## 九 受控处理而非万能修复

处理动作分三种，用户能够看到区别：

1. **准备动作**：用户确认后通过正常会话加载已安装且受信任的技能，或修正任务的输入范围；动作可能留下上下文记录，不能宣称无痕回滚。
2. **可回滚变更**：首版限本插件拥有的任务配置，例如改用用户选定且可访问的输出位置、切换到已具备能力的替代流程。不修改宿主全局模型、权限或其它插件配置。
3. **人工处理指引**：账号重新登录、填写密钥、安装软件、升级宿主、修复其它插件、改变权限等，给出依据与入口，由用户按宿主机制处理。不能显示“已自动修复”。

完整的自动变更事务定义为：生成计划 → 展示范围与预期效果 → 用户确认 → 再核对前置条件 → 执行 → 复检 → 成功，或按本插件自有状态的精确前值恢复。

执行许可绑定计划摘要、会话、动作、参数、版本与有效期；模型参数中不接受 approved=true 作为授权。单次许可不可跨会话复用。已有用户修改、状态代次变化、过期或重复提交会拒绝执行。

中断后先读取已记录的操作状态。对宿主或外部副作用无法证实结果时，标记“结果待确认”，不自动补做或用旧快照覆盖用户的新修改。首版不承诺对任意进程、第三方服务或技能上下文做事务回滚。

## 十 数据与访问边界

- TaskIntent：目的、显式输入引用、输出要求、能力依赖、执行限制、未决问题。默认最多 24 个能力节点；复杂任务要求拆分。
- SessionSnapshot：会话身份、turn/step、模型路由、工具集指纹、目录与权限摘要、适配器版本、取得时间。不是整份环境变量或配置导出。
- Evidence：依据种类、权威来源、最小结构化事实、取得时间、适用范围；错误正文不默认复制。
- Report：逐项状态、阻塞、替代路线、明确边界与建议。UI 与模型读取同一 reportId 和 revision。
- ProbePlan / RemedyPlan：明确动作与风险、预算/超时、前置条件、许可绑定与复检标准。

完整诊断缓存默认保存在本次会话的受限内存中；用户明确保存/导出时才另存到本插件资料区或指定位置。模型工具返回的最小摘要仍会随宿主正常会话日志保存，不能宣称完全不落盘，因此返回模型前也必须按允许字段缩减和脱敏。涉及实际变更的最小操作日志在动作前持久化，用于幂等与恢复，不保存密钥或业务正文。探测执行状态另外记录 planned / running / succeeded / failed / cancelled / outcome_unknown，不把超时后的未知外部副作用当成已撤销。

Remote 必须复用宿主认证连接、严格请求 codec 和会话资源授权。客户端传来的 sessionId 不是授权。首版未通过非 owner 的跨会话访问测试前，不开放这类调用；关闭页面、断连和取消均传播到运行中的探测。

本地摘要可以显示用户需要的具体路径；可分享报告默认隐藏用户名、绝对目录、内网域名、服务器自定义名、原始任务文本及未清洗错误。用户可预览后决定导出，不自动上传或反馈给维护者。

## 十一 可验收的产品行为

以下是未来实现的验收场景，不是当前已通过的产品测试。

| 场景 | 必须满足的结果 |
|---|---|
| 同一任务从自然语言与模板进入 | 形成相同能力依赖时返回同一套诊断含义 |
| 已注册工具因路由条件不可用 | 显示当前未开放，不建议盲目重装 |
| searchReady=true，但后端缺失 | 不显示搜索测试通过 |
| 抓取返回验证码页 | 明确访问受阻，不把页面壳当正文 |
| 模型没有图像能力声明 | 标记声明未知/未声明，不编造视觉检查结果 |
| Office 技能未加载 | 明确准备动作与下一步骤复检要求 |
| Office 工具已准入但服务缺失 | 诊断引擎条件缺失，而非认定可用 |
| 同名工具卸载重装或模型切换 | 旧报告失效，不能复用确认与通过状态 |
| 另一会话请求报告或执行计划 | 服务端拒绝，不靠前端隐藏 |
| 用户拒绝、取消或关闭页面 | 不执行后续副作用，不伪装成环境故障 |
| 宿主 never 审批策略 | 不更改策略，不绕过拒绝 |
| 输出位置已被替换或用户修改配置 | 前置条件失败，不覆盖用户变化 |
| 连点执行或网络重试 | 单次操作不重复，状态可回读 |
| 第三方能力未适配 | 显示未知及替代验证办法，不一律判不支持 |
| 导出诊断 | 无密钥、原始会话或默认暴露的私人路径 |
| 卸载插件 | 其它工具、用户模型和会话不变，历史导出仍可读 |

验证顺序：规则单元测试 → 精确 SDK 的隔离 Host 测试 → Native 与 PTC 双执行器 → 客户端会话切换与错误状态 → 干净 profile 安装、重启、升级与卸载 → 授权的最小真实后端探测。各层独立报告，不相互替代。

## 十二 实现拆分与发布边界

这是工程拆分，不是把用户体验拆成缩水版本：

1. 固定精确宿主基线、插件 manifest 与独立测试环境。
2. 建立报告协议、状态机、能力依赖图及确定性规则。
3. 接入会话快照与首批六类适配器，避免读取或存储凭据。
4. 接入自然语言结构化意图、模板及同源报告入口。
5. 加入探测许可、预算、取消、准备动作与本插件自有状态的可回滚变更。
6. 完成错误矩阵、安装/卸载、跨会话隔离、版本回归和实际用户流程验收。

当前只核验 Mac 上 DSH 0.2.2-rc.2 的接口。Windows、Linux 与其他宿主版本的支持要通过对应测试后再声明；不能因使用 TypeScript 就承诺跨平台已兼容。

发布前还需确认插件名称/包名、许可证与账号，检查依赖和隐私，完成准确版本矩阵。支持计划申请信息不进入公开源码；测试与示例使用合成材料。

## 十三 当前可行性与剩余风险

当前已证实工具作用域、步骤准入、模型选择、沙箱与审批策略存在可利用接口，且工具准入的关键语义可在隔离进程复现。具体证据见[接口核验记录](<接口核验记录.md>)。

仍须在实现阶段重点验证：客户端 Remote 授权的完整接入、精确本轮快照的生命周期、不同执行器的探测调度、实际文档引擎、MCP Fiber 绑定、取消后的资源清理和修复回执。没有这些验证，不对外称插件可用。

本方案建议先实现可安装的完整流程，同时对不具备可靠自动处理接口的项目提供明确人工指引。是否接受这一首发修复边界，是进入实现前需要确认的关键产品决定。
