## 三 与已批准设计的差异

1. **图形界面客户端入口未实现。** 本轮只交付会话内工具、斜杠命令与同源渲染（工具结果渲染与导出共用同一份 Report）。原因：客户端模块契约（`dsh.client`、`exports["./client"]`、`window.__ModuleLoader__` 装载格式）已在本机安装包中核对到清单与产物格式，但本会话没有可用的 GUI 验收环境，无法验证挂载、插槽与交互；把未验证的客户端代码加入日常界面会带来界面故障风险。因此改为下一阶段的独立交付，需要一次允许在真实界面验证的会话。
2. **四类能力不做自动探测。** 图片理解需要新一轮模型请求，浏览器读取需要调用当前会话的浏览器工具，MCP 探测会连接并可能启动进程，文档生成需要宿主 shell 与技能。这四类在报告中显示“未知 + 人工验证办法”，不伪装成不支持或已通过。
3. **探测执行只走已核对的服务接口。** 文件写入使用宿主文件服务的每次调用权限参数，由宿主边界拒绝越权；探测不调用任意工具的执行函数，不直接发起任意 URL、命令或内网请求。固定示例页与一次有上限的查询是内置常量，任务文本不能提供地址。
4. **执行必须经宿主审批。** 只有宿主审批返回 `allowed-once` 才执行；`never` 策略自动拒绝；审批提示文本列出动作、影响、费用与有效期。
5. **持久化域名为 `task_readiness`。** 宿主校验要求域名匹配 `/^[a-z][a-z0-9_]*$/`（首次构建即失败并改正），包名与插件名仍为连字符形式。

## 三之二 同源报告界面

本轮的“报告界面”落在宿主已有的呈现层上，不再另写客户端模块：

- 待执行卡片：`presentCall` 给出“功能体检：<任务名>”、类别与最多 4 个显式输入路径，便于编辑器跟随。
- 完成卡片：`presentResult` 只用 `output.presentationMeta` 投影出的同一份报告记录生成标题与正文，不解析模型文本，因此界面、模型摘要与导出不会各算一套。
- 投影经白名单化：只含报告 id、状态、时间、中文能力标签、逐项状态、路线状态与边界说明；不含会话 id、绝对路径、原始任务文本。
- 动作卡片显示计划状态、回执码与复检状态；计划未执行时明确写“计划已生成，尚未执行”。
- 演示器参数会先按工具参数模式校验；重放旧记录中不合法的参数时回退到通用呈现，不会因历史参数抛错。

仍未实现的是自定义客户端面板（模板选择器、按钮式确认/取消）。原因与本轮处理一致：本会话没有 GUI 验收环境，无法验证挂载与交互，因此改由独立阶段交付。

## 四 未验证层

1. 真实 DSH Host 中的安装、重启、升级与卸载；本轮的隔离验证是“打包产物 + 合成上下文”，不是 profile 安装。
2. 图形界面客户端（未实现，见差异说明）。
3. Windows 与 Linux 运行、路径与进程行为。
4. 真实后端探测：联网搜索、网页抓取、Office 引擎、MCP 连接、浏览器工具均未执行真实调用，相关结论仍属“未测试”。
5. 真实模型路由元数据查询（`resolveModelInfo`）在宿主中的返回、迟滞与失效时序。
6. Remote/跨会话访问的负例测试；当前只验证了服务层的会话隔离。
7. 官方支持计划结果与发布账号、许可证；报名属意向登记，不代表获批。

## 六 隐私与安全边界

- 诊断证据只在内存中按会话保留，报告上限 100 条，动作上限 100 条，探测证据上限 500 条。
- 动作日志只写计划 id、会话 id、动作种类、绑定指纹、时间与结果；不写任务正文、文件内容、密钥或凭据。
- 共享导出是白名单投影；模型可见摘要额外去除会话 id、绝对路径与原始任务文本。
- 探测材料全部为随包合成文件与固定示例页，不发送用户文档。
- 未修改日常 DSH 配置、模型、权限、会话或安装包；未对外发布或提交任何表单之外的内容。
